TOPTECH SOCIAL STUDIO v2.0 — HOSTINGER GITHUB & NODE.JS DEPLOYMENT GUIDE
================================================================================

1. WHY 503 SERVICE UNAVAILABLE HAPPENED PREVIOUSLY (AND HOW IT IS NOW FIXED)
--------------------------------------------------------------------------------
The 503 Service Unavailable error on Hostinger GitHub deployments was caused by:
  a) Node 22 native TypeScript execution (`node server.ts` via `npm start`)
     failing on non-`type` interface imports (`Request`, `ActivityLog`, etc.).
     -> FIXED: All TypeScript interfaces now use explicit `type` imports, so
        `node server.ts` (`npm start`) runs natively on Node 22 without errors.
  b) LiteSpeed `lsnode.js` / Phusion Passenger failing on top-level `await`,
     `app.listen(PORT, '0.0.0.0')` socket binding, and missing `dist/` + `server.js`.
     -> FIXED: Top-level `await` has been removed, `app.listen(PORT)` binds
        synchronously on the first tick, `dist/` and `server.js` (self-contained
        CommonJS bundle) are tracked in Git, and `package.json` uses public
        npm-compatible version ranges (`>=`).

2. DEPLOYING FROM GITHUB ON HOSTINGER (STEP-BY-STEP)
--------------------------------------------------------------------------------
1. Push/sync this updated codebase (including `server.js` and `dist/`) to your
   GitHub repository (`SocialSetup`).
2. In Hostinger hPanel -> Websites -> Manage -> Node.js:
   - Node.js Version: 22.x (recommended) or 20.x
   - Application Startup File / Entry File: `server.js`
3. Under Hostinger Environment Variables, add your variables from
   `toptech_social_studio_free_ai.env` (specifically `NODE_ENV=production`,
   `ADMIN_PASSWORD`, `SESSION_SECRET`, and optional `GEMINI_API_KEY` /
   `META_PAGE_ID` / `META_PAGE_ACCESS_TOKEN`).
   Note: Even if you deploy before setting environment variables, the server
   will start cleanly and guide you on the login screen and Login Info tab.
4. Click "Deploy" (or "Redeploy") under Deployment from GitHub.
5. Verify health at:
   https://<your-domain>/api/health
